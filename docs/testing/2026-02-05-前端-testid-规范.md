# 前端 data-testid 规范（v2）

日期：2026-02-05（最后更新：2026-04-16）

## 目标
- 提供稳定、可维护的测试选择器
- 避免依赖文案或样式导致的脆弱定位
- 保持与当前产品术语和 current IA 一致

## 命名规则
- 格式：`scope__element__state`
- 分隔符：双下划线 `__`
- 示例：
  - `login__submit`
  - `projects__create-btn`
  - `agents__table`
  - `page-state__error`
  - `notebook__task-header`

## 唯一性边界
- `surface` 容器 test id 必须在当前场景里唯一，适合作为 story / visual semantic contract 的锚点。
- 列表行、卡片、表格项这类重复项允许复用同一 test id 族，但不要把它们直接当成 page-global 语义锚点。
- 当同一页面里某个目标 test id 会在多个 surface 重复出现时，必须用 `surface::target` 收敛断言边界，而不是继续把 `target` 当成整页唯一 marker。
- `surface::target` 里的 `surface` 和 `target` 都继续遵守 `scope__element__state` 命名规则。

## semanticAssertions 允许的语义族
- `requiredViewportTestIds`：要求目标在首屏 viewport 内可见。
- `requiredViewerLocalDateTimeTestIds`：要求目标暴露 viewer-local datetime 元数据。
- `primaryActionTestIds`：要求目标是当前场景的 CTA / primary action。
- `prominentActionScopeTestIds`：要求 story 显式给出统计 prominent action 的唯一 scope 容器。
- 以上三类都允许直接写 `target`，也允许写 `surface::target`。
- `prominentActionScopeTestIds` 只写 scope 容器 test id，不写 `surface::target`，因为它本身就是当前统计边界。
- 只有在 target 已经天然 page-unique 时，才适合直接写 `target`。
- 一旦使用 `surface::target`，`surface` 必须是当前场景里唯一且可见的 surface 容器，也就是当前断言的“唯一 surface”边界。
- `prominentActionScopeTestIds` 里的每个值也必须是当前场景里唯一且可见的 scope 容器。

## 推荐模式
- page-global 唯一目标：`notebook__create-task-btn`
- surface-aware 目标：`system-workspaces__editor::system-workspaces__save`
- header CTA：`page-layout__header::system-workspaces__new-workspace`
- dialog CTA：`system-workspaces__delete-dialog::system-workspaces__delete-confirm`

## 使用原则
- 必须稳定：不随文案/样式变化
- 必须在断言边界内唯一：page-global target 要整页唯一，surface marker 要当前场景唯一，`surface::target` 里的 target 只需要在该 surface 内唯一
- 必须覆盖关键路径：登录、项目入口、Chat、Notebook、治理入口、发布前高价值页面
- testid 命名应直接跟随当前产品术语与页面对象名
