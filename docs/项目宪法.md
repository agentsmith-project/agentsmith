# AgentSmith 项目宪法

本文档用于约束当前产品目标、边界与治理原则，避免范围漂移。

## 一、定位

AgentSmith 是 MBOS 的企业级控制面，服务工作区与项目中的 AI 使用、资源治理与审计。

当前产品职责：

1. 企业级 AI 智能体使用与管理
2. 项目级 AI 资源治理
3. 项目级审计与用量追踪

## 二、范围

在范围内：

1. 认证与身份
2. 工作区与项目
3. Chat / Notebook / Files / Agents / Endpoints
4. 资源策略（project scope）
5. 成员与凭据
6. 审计与用量
7. 运行观测（Runtime Console）

不在范围内：

1. DevOps 发布编排与发布管理平台能力
2. 组织级统一资源治理总控（跨 project 汇总治理）
3. Chat/Notebook 独立限额体系
4. 文件级策略

说明：如仓库内出现 `release` / `gate` 命令命名，属于项目研发流程术语（验收/排障/报告），不构成产品功能范围。

## 三、治理主线

唯一主线：项目级 LLM endpoint 统一约束链路。

统一约束适用面：

1. Chat
2. Notebook
3. 用户 API 调用

约束与证据：

1. rate limit
2. spending limit
3. policy/audit evidence
4. usage evidence

## 四、架构与权限原则

1. 后端是唯一权威；前端门禁不替代后端鉴权。
2. 权限判断只认 permission token，不以角色名做运行时门禁。
3. URL 是工作区/项目上下文真相源。
4. 路由参数必须先校验再用于请求和门禁。

## 五、工程约束

1. 生产代码禁止 `any`。
2. 用户可见文案必须 i18n 化。
3. 受保护路由必须有门禁契约检查。
4. 合约优先，接口与前端类型保持一致。

## 六、防漂移清单

禁止：

1. 把系统扩展为发布管理/DevOps 平台
2. 引入组织级治理总控叙事作为当前主线
3. 用角色名/治理分组名替代权限 token 鉴权
4. 在无合同定义前新增治理维度与策略对象
