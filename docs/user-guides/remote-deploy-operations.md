# Remote Deploy Operations

`docs/contracts/deployment-spec-v1.md` is the deployment contract. This guide is the short operator runbook for the current remote deployment flow.

## Host

- Remote host: `percy@192.168.0.220`
- Remote deployment root: `/home/percy/agentsmith/deploy`
- Shared operator config: `/home/percy/agentsmith/deploy/config/site.env`

Everything under `/home/percy/agentsmith/deploy` is managed deployment state. Do not copy release files into `$HOME` or patch random working directories.

## Directory Model

- `current`
  - Symlink to the active release directory.
- `uploads`
  - Uploaded offline bundles.
- `releases`
  - Extracted release directories.
- `config/site.env`
  - Single operator-edited deployment config source.
- `state`
  - Generated deploy/bootstrap/runtime state.
- `logs`
  - Deployment logs and helper output.
- `reports`
  - Generated verification reports.

## Topology

- Docker Compose services:
  - `postgres`
  - `mongo`
  - `redis`
  - `minio`
  - `keycloak`
  - `api`
  - `web`
  - `universal-proxy`
  - `external-runner`
- `kind` cluster services:
  - `sandbox-manager`
  - `juicefs-csi-controller`
  - `juicefs-csi-node`
  - internal agent workload pods

External dependencies stay in Compose. Internal agent workloads use Kubernetes service names that point to those external dependencies.

## Current Address Model

- Browser/public access:
  - `PUBLIC_WEB_BASE_URL`
  - `PUBLIC_API_BASE_URL`
  - `PUBLIC_KEYCLOAK_BASE_URL`
- Client JuiceFS mount instructions:
  - `CLIENT_PUBLIC_POSTGRES_HOST`
  - `CLIENT_PUBLIC_POSTGRES_PORT`
  - `CLIENT_PUBLIC_MINIO_ENDPOINT`
- Internal agent execution:
  - Kubernetes service names for external PostgreSQL and MinIO
- External runner execution:
  - Runner-visible JuiceFS metadata/storage overrides generated by deploy/bootstrap

UI-facing file library mount instructions must use client-visible addresses. They must not show `localhost`, `postgres`, `minio`, Docker bridge addresses, or `host.docker.internal`.

## Standard Flow

From the active release directory:

```bash
cd /home/percy/agentsmith/deploy/current
bash scripts/prepare.sh
bash scripts/deploy.sh
bash scripts/bootstrap.sh
bash scripts/verify.sh
bash scripts/report.sh
```

Reset when you need a clean redeploy:

```bash
cd /home/percy/agentsmith/deploy/current
bash scripts/reset.sh
```

## Current Good State

- `current` points to the active release under `/home/percy/agentsmith/deploy/releases/...`
- `config/site.env` contains the operator-owned deployment config
- `deploy` can recreate an unhealthy `kind` cluster automatically
- JuiceFS CSI runs on `v0.31.3`
- `bootstrap` reuses or recreates the canonical external runner container as needed
- `verify` runs from the bundled release assets, not ad hoc host source trees

## What Not To Do

- Do not patch release files in random directories under `$HOME`
- Do not rely on manual SQL fixes or Keycloak console edits
- Do not hot-edit generated `env/*.env` files as the source of truth
- Do not treat historical bundles under `uploads/` or historical releases under `releases/` as the active deployment
