# Usage / Audit MVP 功能与 UX 定义 v1

## 1. 目标

在 MVP 范围下，将 AgentSmith 的治理相关产品面收敛为两类：

1. `Usage`：用户看自己的资源用量与限制消耗程度。
2. `Audit`：管理员看资源、配置、状态与异常事件的记录。

本文件只定义当前 MVP 对外功能与 UX/UI 原则，不讨论未来扩张形态。

## 2. 最小产品对象模型

当前 MVP 只允许前端围绕以下 5 类对象组织功能：

1. `Resource`
2. `UsageRecord`
3. `LimitRecord`
4. `ConfigurationChange`
5. `SystemEvent`

禁止继续把以下对象当作一等产品概念暴露或围绕其组织界面：

1. `guardrails`
2. `probe`
3. `alias`
4. `combo`
5. `routing`
6. `activation`

## 3. Usage 的 MVP 功能定义

### 3.1 要回答的问题

1. 我现在在用哪些资源？
2. 我在每个资源上的 rate / spending 消耗到什么程度？
3. 哪个时间窗口快达到限制？

### 3.2 页面结构

1. 顶部：简短标题与时间范围控制。
2. 资源切换：按资源 tab 或等价低心智切换器。
3. 当前资源限制卡：按 `rate limit` / `spending limit` 与窗口展示进度。
4. 趋势区：只展示帮助用户判断近期消耗变化的简明图形。

### 3.3 UX 原则

1. 默认看进度，不要求用户理解复杂数值。
2. 不做跨资源总量汇总。
3. 不出现管理员术语和治理动作。
4. 不出现实现细节术语。

## 4. Audit 的 MVP 功能定义

### 4.1 要回答的问题

1. 最近系统和资源发生了什么变化？
2. 谁改了什么？
3. 哪些资源出现了异常或风险？
4. 我需要进一步去哪里处理？

### 4.2 页面结构

1. 顶部概览条
- 最近 24h / 7d 关键事件数
- 配置变更数
- 异常事件数
- 受影响资源数

2. 主体事件流
- 时间倒序
- 每条卡片展示：时间、资源、事件类型、操作人/来源、一句摘要

3. 详情抽屉
- 变更前/后
- 关联对象
- 相关状态
- 必要原始记录

4. 基础筛选
- 时间范围
- 资源
- 事件类型
- 操作人

### 4.3 UX 原则

1. 审计页面首先是“看记录”，不是“做编排”。
2. 首屏默认应该帮助管理员快速扫描变化与异常。
3. 详情只在需要时展开，不把技术细节堆到主列表。
4. 不要求用户理解内部机制对象。

## 5. 不在 MVP 范围内

以下能力不进入当前 MVP：

2. 复杂资源编排台。
3. 复杂模拟、预演、验证工作台。
4. DevOps 发布、门禁、发布运营叙事。
5. 围绕内部机制对象组织的产品体验。

## 6. 文案原则

1. 尽量使用“资源、用量、限制、变更、事件、状态、异常”这些稳定词。
2. 不把内部实现词翻译后继续塞给用户。
3. 如某概念不能用一句人话解释清楚，则默认不进入 MVP UI。

## 7. 设计检查清单

在开始实现前必须确认：

1. 这个功能属于 `Usage` 还是 `Audit`？
2. 它围绕的对象是否属于最小产品对象模型？
3. 它是否引入了额外术语层级？
4. 它是否让用户必须理解实现细节才能完成任务？
5. 它是否在扩大 MVP 范围而不是收敛？
