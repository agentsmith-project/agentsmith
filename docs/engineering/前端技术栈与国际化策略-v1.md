# 前端技术栈与国际化（i18n）策略 v1

日期：2026-04-11  
适用：Web 前端（system 管理侧 + workspace/project surfaces + Chat + Notebook + Files）

## 1. 技术栈

- 框架：Next.js（React）+ TypeScript
- UI：TailwindCSS + Radix UI
- 图标：Lucide
- i18n：next-intl

约束：
- UI 必须支持数据密集场景，不以装饰性留白为主
- Light 是当前默认交付面；tokens 与组件组织不能阻塞后续 Dark 扩展
- 全局 UI 风格指导看 [DESIGN.md](../../DESIGN.md)

## 2. 国际化范围

当前必须支持：
- `zh-CN`
- `en-US`

所有用户可见文本必须来自 i18n 字典：
- `src/messages/en-US.json`
- `src/messages/zh-CN.json`

数字、时间、相对时间必须本地化；`error_code`、`request_id` 这类排障主键不翻译。

## 3. i18n 结构规则

- key 使用 `snake_case`
- 两个 locale 文件必须保持同一结构
- 顶级 namespace 按当前产品对象划分，例如：
  - `common`
  - `nav`
  - `auth`
  - `workspace`
  - `project`
  - `chat`
  - `notebook`
  - `files`
  - `agents`
  - `endpoints`
  - `members`
  - `audit`
  - `usage`
  - `settings`

当前产品命名遵守 [Product Terminology Contract](../contracts/product-terminology.md)。新增用户可见文案时，直接复用当前正式对象名，不在工程文档里维护一份旧名对照表。

## 4. 最小实现规则

- 优先复用已有 key，不为同一意思重复造 key
- 通用按钮、状态、提示放在 `common`
- 页面/模块专属文案放在对应 namespace
- 带参数文案统一用 `{name}` 风格占位符
- 组件内优先只声明一次 `useTranslations()`；子组件需要时优先通过 props 传递或在独立复用场景下自行取更细 namespace

## 5. 开发工作流

推荐顺序：
1. 先确认当前产品命名与 IA 边界
2. 先补 `en-US.json` 与 `zh-CN.json`
3. 再在组件中替换硬编码用户可见字符串
4. 最后做中英文双语自测

至少回归：
```bash
npx tsc --noEmit
npm run test:run
```

如变更影响关键 UI 表面或截图证据，再补：
```bash
npm run verify -- --goal=visual --run
```
