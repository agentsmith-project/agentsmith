# 页面清单（v1）：模块、权限可见性与关键字段

日期：2026-01-31

---

## 1) 约定

- 权限采用 token-first：UI 分组（模板）仅作为权限点集合的便捷封装，门禁判断必须基于 token 集合
- “只读可见”与“可管理”必须在 UI 上明确区分（按钮/入口是否出现）
- 任何危险操作（revoke key、rotate credential、删除 endpoint/source library/agent）必须二次确认并记录 request_id

---

## 2) 页面清单（v1）

### 2.1 登录与全局
- Login（JWT）
- Workspace Switcher（列表/搜索）
- Workspace Settings（工作区设置）
- Profile（基本信息、退出）
- User API Keys（usk 管理：创建/查看/撤销）

### 2.2 Project
- Project List/Discover
  - join 状态（member / pending / not_member）
- Project Overview
  - KPI：turns、errors、queued、online agents、endpoint requests、token usage

### 2.3 Notebook
- Notebook Workspace（NotebookLM-like 布局）
  - 列表页采用紧凑任务列表（compact rows）优先，首屏提升任务可见数量
  - 布局密度：使用沉浸式密度（PageLayout `immersive`，外圈间距 8px）以提升空间利用率
  - 左侧 Files：文件上传/列表/状态（queued/processing/retrying/ready/failed）
  - Source library 切换必须作为单一上下文切换：文件列表、文档索引状态、向量索引状态一起切换
  - 切换后立即清空旧库视图并按新 `source_library_id` 重拉，禁止混合展示
  - 中间 Thread：消息区（SSE 流式输出）
  - 右侧 Context：current agent、handoff、thread 状态与操作（close/cancel）
- Threads List（可选：如不做单独列表页，则在 Notebook 顶部提供 thread 切换器）
- 门禁（MVP）：仅页面访问级
  - `project:endpoint:use` 决定 Notebook 是否可访问
  - 页面内部动作不再做细粒度 token 拆分

### 2.4 Agents
- Agents List
  - mode（external/internal）
  - presence（online/offline/managed）
  - status（enabled/disabled）
  - active_sessions（internal）
- Agent Detail
  - 基本信息
  - internal config（`project:agent:manage` 可编辑）
  - managed_diagnostics（`project:agent:manage` 可见 message）
- Agent Keys（ask）
  - create/suspend/resume/revoke

### 2.5 Endpoints
- Endpoints List/Detail
  - openai_model、status、limits 摘要
  - 列表中直接展示关键限额摘要：`RPM` 与 `Tokens/day`
  - 动作按钮在桌面端使用“图标 + 文本”（Edit / Enable|Disable / Delete），降低误操作
  - disable/enable/rotate（`project:endpoint:manage`）
- Endpoint ACL（deny list）
  - 搜索用户、添加 deny、移除 deny

### 2.6 Members
- Members（顶层单层结构）
  - People（成员列表、筛选、权限与配额抽屉）
  - Join Requests（审批）
  - Templates（权限模板、配额模板）
  - Groups（项目组与模板批量应用）
  - People 页在可批量操作场景下需要预留底部操作条空间，避免“选择后表格跳动”

### 2.6.1 Resource Policy
- Resource Policy（统一资源策略）
  - 资源分组：Endpoint / Agent / Source Library
  - 左侧资源列表 + 右侧编辑器（访问模式、主体覆盖、资源限额、生效摘要）
  - 资源默认策略可被主体覆盖（user/group），并在“生效摘要”中展示来源（resource vs subject）

### 2.7 Audit & Usage
- Audit（按 action/resource/actor 过滤）
- Usage（按 resource_type、agent、end_user 过滤；图表+表格）

### 2.8 Settings
- Project Config（给 agent 读的结构化 config）
- Project Policy（配额/限流/护栏/能力开关）
### 2.9 Chat（必须，v1）
- Chat Workspace（NotebookLM-like 布局）
  - 布局密度：使用沉浸式密度（PageLayout `immersive`，外圈间距 8px）以提升空间利用率
  - 左侧 Files：文件上传/列表/状态（同 Notebook，可复用）
  - Source library 切换逻辑与 Notebook 保持一致：切库时三元组上下文一起切换并重拉
  - 中间 Chat：OpenAI chat.completions UI（流式输出）
  - 右侧 Context：model（openai_model）选择、基础参数（v1 可不做高级参数）
- 门禁（MVP）：仅页面访问级
  - `project:endpoint:use` 决定 Chat 是否可访问
  - 页面内部动作不再做细粒度 token 拆分

## 3) E2E 覆盖矩阵（当前基线）

- `overview`
  - KPI 卡片渲染、时间范围切换、Quick Access 入口可见性与可点击性
- `projects`
  - 列表渲染、搜索过滤、创建项目（含 `visibility` / `join_policy`）、进入 Overview、进入 Settings、删除项目
- `chat`
  - 会话列表渲染、搜索、模型选择器、输入发送（Enter 路径）
- `notebook`（Notebook）
  - 列表渲染、任务详情页进入、消息区/附件区/产物区关键控件可见性
- `files`
  - 列表渲染、搜索、状态筛选、排序切换、上传入口可见性
- `agents`
  - 列表渲染、状态切换、外部 agent key 操作入口、创建/编辑/删除基础路径
- `endpoints`
  - 列表渲染、创建/编辑/删除、启停切换、`RPM` + `Tokens/day` 展示、请求 payload 校验
- `resource-policy`
  - 资源分组渲染、访问模式切换、主体覆盖增删、限额输入、生效摘要变化与保存
- `members`
  - 单层顶栏（People / Join Requests / Templates / Groups）、筛选/搜索、邀请、权限抽屉、模板与分组应用路径
- `credentials`
  - 列表渲染、创建/轮换/删除弹窗、提交校验、请求 payload 校验
- `audit`
  - 列表与过滤器渲染、行操作详情抽屉
- `usage`
  - KPI/列表渲染、过滤器交互、清空过滤器
- `settings`
  - 仅保留 `General` / `Runtime Preferences`，移除遗留治理与限制页签
- `navigation`
  - 侧边栏全入口、折叠/展开、Topbar workspace/project 切换器、用户菜单（profile / api keys / language / logout）
- `account`
  - Profile 编辑保存（含请求校验）、User API Keys 创建/展示/撤销（含请求校验）

### 3.1 不在本轮 E2E 范围

- 与后端真实鉴权/edge 联调（当前仅校验前端页面门禁与交互契约）
- 大规模性能压测与长稳态压测（另行专项）
