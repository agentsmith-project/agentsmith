# 视觉基线审查与交付规范 v1

Status: `active`
Depends on: [`DESIGN.md`](../../../DESIGN.md), [`站点页面配方与壳层规范-v1`](./站点页面配方与壳层规范-v1.md)
Scope: `interaction / product behavior`
Does not define: `global tokens / route truth / engineering gates`

## 1. 目标

定义 AgentSmith 的 visual baseline 如何重建、如何审查、如何接受，确保每张截图都能反推到明确的页面 recipe、代码实现和 Cursor 风格判断。

## 2. 必要证据

每张可接受的 baseline 必须能追溯到以下信息：

1. route
2. theme
3. recipe family
4. story / scenario
5. 代码参考点
6. 截图文件
7. 审查结论

缺任一项都不应作为已完成的基线接受。

## 3. 重建流程

1. 先看 route code 和共享 recipe 使用情况。
2. 再看实际渲染截图，不只看 DOM 或测试通过结果。
3. 对照当前公开 Cursor 界面判断 shell 重量、间距、排版和动作层级。
4. 必须分别检查 light 和 dark，不允许只看单主题。
5. 若 screenshot 暴露 recipe 漂移，先改代码，再重跑 baseline，不能靠注释解释通过。

## 4. 审查规则

### 4.1 代码审查

必须确认：

1. 页面是否只使用允许的 recipe family。
2. 是否存在额外 page-local shell 或 wrapper。
3. CTA、state、overlay 是否使用共享 primitives。
4. 是否有违反 `DESIGN.md` 的页面私有视觉语言。

### 4.2 截图审查

必须确认：

1. 页面第一眼是否像 Cursor 的安静工作面，而不是 dashboard 或 marketing page。
2. light / dark 是否保留相同拓扑和控制位置。
3. 主动作是否清楚但不过分抢眼。
4. 是否有重卡片、重渐变、重阴影、过亮 shell 或 chooser stack。

### 4.3 Cursor 对齐审查

必须确认：

1. shell 比内容更轻。
2. 页面是由 spacing、type rhythm、分隔线和轻量 surface 组织，而不是由卡片墙组织。
3. 视觉差异只来自主题和层级，不来自另一套 UI 语言。

## 5. 接受标准

只有同时满足以下条件，baseline 才能接受：

1. 代码已经落在正确 recipe family。
2. 截图在 light / dark 下都符合当前 Cursor 风格。
3. 没有额外 shell、dashboard trope、marketing trope 或 page-local decorative language。
4. 关键状态有对应的 shared state 语法。
5. 没有只因为测试通过就接受的情况。

## 6. 拒绝标准

以下任一情况都必须拒绝该 baseline：

1. route 与 recipe family 不匹配。
2. 截图显示出新的视觉语言分叉。
3. 单独某个主题通过，但另一个主题构图或层级明显漂移。
4. 页面出现 chooser card stack、summary strip、双主栏、重 overlay 或其他高噪声结构。
5. baseline 仅凭“功能没变”被接受。

## 7. 交付规则

1. baseline 更新必须是 family 级，而不是零散单张图。
2. 每次更新后必须留下可追溯的审查记录。
3. 若后续再发现 recipe 漂移，应该回到代码修正，不应继续接受偏差截图。
4. 所有最终交付截图都要证明 AgentSmith 在站点级别统一到 Cursor 风格，而不是局部页面看起来像。
