# `mbos.imotion.ai` Remote Deploy Runbook

`docs/contracts/deployment-spec-v1.md` is the single source of truth for deployment topology, env contracts, bundle contents, bootstrap stages, and verification requirements. This runbook only explains how to execute that spec.

## Goal
- Clear the old AgentSmith test environment.
- Deploy one clean offline-ready environment.
- Run Compose on the host for system services.
- Run kind + JuiceFS CSI + sandbox manager for internal agents.

## Standard Flow
1. Build a local offline bundle.
2. Upload the bundle to the target host.
3. Extract it into `/home/mbos/agentsmith-deploy/releases/<release-id>`.
4. Edit exactly one deployment config file:
   - `env/site.env`
5. Run:
   - `scripts/remote-deploy/prepare.sh`
   - `scripts/remote-deploy/reset.sh`
   - `scripts/remote-deploy/deploy.sh`
   - `scripts/remote-deploy/bootstrap.sh`
   - `scripts/remote-deploy/verify.sh`
   - `scripts/remote-deploy/report.sh`

## Notes
- The target host must not pull public images during deploy.
- All images are expected to be preloaded from the offline bundle.
- Compose owns host services.
- kind owns internal agent runtime.
- JuiceFS CSI is the only internal workspace persistence model.
- `env/site.env` is the only editable deployment config source.
- Service env files are generated automatically during deploy.
- `env/runner-runtime.env` is generated by bootstrap and must not be edited manually.
