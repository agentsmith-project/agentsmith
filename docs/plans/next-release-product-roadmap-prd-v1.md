# AgentSmith 下一期产品路线图 PRD（v1）

更新时间：2026-02-26  
适用周期：下一迭代（建议 8 周）  
目标读者：产品、研发、测试、实施、运维

---

## 1. 背景与目标

当前版本已完成：
- 主线（Files -> Notebook -> Agent -> Trace -> Artifacts）可演示、可回归、可发布
- 治理（Members / Resource Policy / Audit / Usage）具备真实后端路径与发布 smoke 门禁

下一期目标从“可发布”升级到“可规模化、可运营、可销售”：
1. 治理从“可配置”升级为“可证明生效”
2. 安全与合规从“内部可接受”升级为“对外可审计”
3. 管理员价值从“后台可用”升级为“业务可运营”

---

## 2. 产品北极星与成功指标

## 北极星
- 成为“可治理的 Agent 运营控制台”，而不是仅“可运行 Agent 的后台”。

## 发布成功门槛（本期）
1. 治理执行一致性
- 指标：策略生效率 >= 99%（策略命中时，实际拦截/放行与预期一致）

2. 安全链路完整性
- 指标：SSE ticket 覆盖率 100%，JWT query fallback 关闭

3. 治理证据可追溯
- 指标：关键治理动作审计完整率 >= 99.9%（actor/time/target/action/policy snapshot）

4. 运营可观测性
- 指标：成本与配额告警可用率 >= 99%，误报率 <= 5%

5. 发布可靠性
- 指标：`make verify-release` 通过率（主干）>= 95%，失败可自动分类归因

## 3. 目标用户与核心场景

## 用户分层
1. 平台管理员（Platform Admin）
- 关心组织级安全、成本、合规、发布风险

2. 项目管理员（Project Admin）
- 关心成员权限、资源策略、配额、审计追责

3. 实施/运维（Delivery/Ops）
- 关心环境健康、故障恢复、可重复交付

## 核心场景
1. 权限与资源策略变更后，能被后端真实执行并可证明
2. 超配额/越权/限流事件能被及时发现、告警与追责
3. 发布前后有稳定门禁与可归档报告

## 4. 范围（In / Out）

## In Scope（本期必须）
1. 治理后端执行闭环
- Members 权限模板/自定义权限/分组权限统一进入后端决策链
- Resource Policy 各资源类型规则执行补齐（endpoint/source_library/agent）

2. 安全加固
- SSE ticket 化
- 关键敏感动作审计字段标准化

3. 运营能力
- 基础成本与配额看板
- 阈值告警（请求量、配额消耗、错误率）

4. 发布门禁升级
- 发布报告结构化归档（commit/env/checks/evidence）

## Out of Scope（本期不做）
- 多云多区域调度优化
- 复杂审批工作流（多级审批/跨组织）
- 商业计费系统对接（账单/发票）

## 5. 产品方案（Epic 级）

## Epic A：治理执行一致性（P0）

### A1. 权限决策链统一
需求：
- 后端 route authz 使用统一授权引擎，消除旁路判断
- 支持来源解释（模板权限/自定义权限/组权限）

验收标准：
1. 任一成员权限判定可返回 explain（可用于 UI 展示）
2. 新增/变更权限后，在 1 次请求周期内生效
3. 发布 smoke 覆盖 deny->grant->allow 与 rollback

### A2. 资源策略执行补齐
需求：
- endpoint/source_library/agent 的 rate/quota/access 行为一致
- 策略优先级稳定：subject > resource > project-default

验收标准：
1. 规则命中与优先级可通过用例证明
2. deny/rate/quota 均有审计与用量证据
3. 回滚策略后行为恢复且有审计记录

---

## Epic B：安全与合规（P0）

### B1. SSE ticket 化
需求：
- 新增 ticket 交换接口，SSE 不再携带长期 JWT query

验收标准：
1. SSE 链路 100% 走 ticket
2. fallback 关闭后主线与治理 smoke 全通过
3. 安全扫描不再命中 JWT query 风险项

### B2. 审计字段标准化
需求：
- 审计动作统一结构：actor/target/action/at/request_id/diff(optional)

验收标准：
1. 关键治理动作 100% 写审计
2. 审计可导出（CSV/JSON）

---

## Epic C：运营与市场吸引力（P1）

### C1. 成本与配额看板
需求：

验收标准：
1. 支持按 workspace/project/resource_type 过滤
2. 图表与明细可联动钻取

### C2. 告警中心（基础版）
需求：
- 阈值告警：requests/day、quota%、error-rate

验收标准：
1. 告警规则 CRUD 可用
2. 告警触发有防抖与恢复通知

---

## Epic D：交付与发布工程化（P0）

### D1. 发布报告自动化
需求：
- `verify-release` 输出结构化报告（json + markdown）
- 自动记录 commit range、环境、执行结果、失败摘要

验收标准：
1. 每次发布验证后可一键归档
2. 报告可直接用于 release note

### D2. 故障分类与排障手册升级
需求：
- 失败自动标记类别（token/network/backend/assertion）
- 对应修复建议与文档链接

验收标准：
1. 常见失败分类命中率 >= 90%
2. 平均排障时间下降（基线对比）

## 7. 依赖与风险

## 关键依赖
1. 后端统一授权引擎改造窗口
2. Keycloak/身份侧 claims 与成员模型一致性
3. 监控与告警基础设施（日志/指标/webhook）

## 主要风险
1. 授权链改造引发历史行为变化
- 应对：灰度开关 + 双写校验 + 回滚脚本

2. SSE ticket 切换影响现网稳定
- 应对：并行链路灰度 + 监控熔断 + fallback 仅短期保留

3. 运营看板数据口径不一致
- 应对：先定义统一口径字典并冻结

## 12. SSE ticket 切换最佳实践（执行方案）

为兼顾安全与稳定，采用分阶段灰度（推荐）：

1. Day 1-2：双栈可用
- 默认仍走旧链路，新增 ticket 链路可用并打埋点
- 指标对比：连接成功率、首包时延、断线重连率、401/403 比例

2. Day 3-5：灰度放量
- 按项目/租户分批切到 ticket（建议 10% -> 30% -> 60%）
- 任何阶段超过阈值（错误率、时延）自动回退到上一档

3. Day 6-7：全量切换
- 默认全量走 ticket，保留短期回退开关
- 连续稳定后删除 JWT query fallback 路径

回退与门禁：
- 必须保留运行时开关（env/配置）用于秒级回退
- 发布门禁增加 ticket 专项 smoke（连接、续期、重连）
- 发布后观察窗口至少 60 分钟
