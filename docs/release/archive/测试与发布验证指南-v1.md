# 测试与发布验证指南 v1（面向开发/测试/实施）

更新时间：2026-02-26  
适用范围：AgentSmith（Notebook 主线 + Governance 治理）

## 1. 这份文档解决什么问题

当你不熟悉项目术语和命令时，最常见问题是：
- 不知道先跑哪个命令
- 不知道失败后该看哪里
- 不理解 `governance`、`contracts`、`strict` 这些词

本指南提供：
- 名词解释（通俗版）
- 按角色的推荐命令
- 发布前最小必跑清单
- 失败排查顺序

---

## 2. 先记住 8 个高频术语

1. `mainline`（主线）  
Notebook / Agent / Files / InputRefs 这条核心业务链路。

2. `governance`（治理）  
谁能访问资源、每人每天/每分钟可用多少、以及审计/用量证据。

3. `contracts`（契约）  
前后端约定（API 字段、行为、路由类型等）。  
契约检查用于防止“前后端不一致”。

4. `smoke test`（冒烟）  
快速验证“主要功能还活着”的端到端检查，不追求覆盖所有细节。

5. `release smoke`（发布冒烟）  
发布前必须跑的一组组合冒烟，通常包含 token 自动恢复与关键效果校验。

6. `strict` / `tolerant`  
- `strict`：更严格，页面出现产品错误态就失败（用于发布门禁）  
- `tolerant`：更宽松，允许部分错误态，主要用于排障定位

7. `demo-check`  
非破坏性检查：进程是否在线、token 是否有效、关键 endpoint 是否可达。

8. `release gate`（发布门禁）  
“不通过就不能发”的检查集合。

## 3. 你只需要记住这些入口命令

## 日常开发最简入口

```bash
make dev-up
make smoke-main
make smoke-governance
make dev-down
```

## 发布前推荐入口

```bash
make verify-release
```

它会执行：
1. `verify-contracts`（typecheck + openapi/generated + contracts checks）
2. `smoke-all`（mainline + governance release smoke）

---

## 4. 按角色推荐使用方式

## 4.1 开发者（功能改动后自检）

最小步骤：
1. `make dev-up`
2. `make smoke-main`（改主线时）
3. `make smoke-governance`（改治理时）

如果改了 API/契约相关：
1. `make verify-contracts`

## 4.2 测试同学（回归/验收）

建议步骤：
1. `make dev-up`
2. `make smoke-all`
3. 失败时单独跑分支命令定位（如 `make smoke-governance`）

## 4.3 实施/发布同学（上线前）

建议步骤：
1. `make verify-release`
2. 记录通过时间、commit 范围、执行环境
3. 发布后观察窗口（30-60 分钟）

---

## 5. 哪些命令是“发布级别必须通过”

当前建议门禁：
1. `npm run ws:typecheck`
2. `npm run openapi:check-generated`
3. `npm run contracts:check-openapi`
4. `make notebook-agent-release-smoke-full`
5. `make governance-release-smoke`

说明：
- `governance-release-smoke` 已使用 strict 页面门禁
- mainline/governance 都支持 token 过期自动刷新重试（一次）

---

## 6. 失败时怎么排查（固定顺序）

1. 先看进程状态  
`make notebook-agent-demo-status`

2. 再看 token 是否有效  
若失效先执行：`make notebook-agent-refresh-token`

3. 再看基础连通性  
- API：`http://localhost:20000/api/v1/openapi.json`  
- Web：`http://localhost:3001/zh-CN/login`

4. 再看具体 smoke 日志  
- `/tmp/agentsmith_demo_api.log`
- `/tmp/agentsmith_demo_web.log`
- `/tmp/agentsmith_demo_runner.log`

5. 若治理页面失败，判断模式  
- `strict` 失败：发布应阻断  
- `tolerant` 失败：说明问题更严重（排障优先）

---

## 7. strict / tolerant 什么时候用

发布判断：只认 `strict`。  
本地排障：可以用 `tolerant` 帮你继续跑到后续步骤，收集更多线索。

相关命令：
- `make governance-pages-real-backend-smoke-strict`
- `make governance-pages-real-backend-smoke-tolerant`
- `make governance-pages-real-backend-interaction-smoke-strict`
- `make governance-pages-real-backend-interaction-smoke-tolerant`

---

## 8. 常见误区

1. “`demo-check` 通过就一定全通过”  
不一定。运行过程中 token 可能过期，所以 release smoke 仍需执行。

2. “只跑主线不跑治理也能发布”  
不建议。治理现在已纳入发布级验证。

3. “contracts 检查可以跳过”  
不建议。跳过后常见风险是前后端字段不一致导致线上回归。

## 9. 一页版发布流程（可复制）

```bash
make dev-up
make verify-release
```

- 执行时间
- 执行人
- 环境（host/API/WEB）
- commit range
